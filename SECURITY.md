# Security and transparency

The current independent collector is blocked before requesting a key or opening a network client; no authorized complete game data source is implemented. Do not use it for live matches. Review the code and applicable game rules before use. A read-only design and automated scans do not guarantee safety or permission.

## Data boundary

The client sends versioned game telemetry to https://deutsche-deadlock-community.de/twitch/api/v3/live-match using HTTPS, a channel-specific bearer key and a 32 KiB body limit. The intended wire fields are documented in docs/contract. No screenshots, player names, Steam IDs, raw process memory, actual match IDs, credentials in the JSON, or arbitrary local files are intended to be uploaded. The future connection-key path uses bounded, non-echoing terminal input (128 input bytes, 512 input events), zeroizing application-owned buffers and direct HTTPS without implicit proxies; the key belongs only in the Authorization header. Invalid input exits; restart to retry. No guarantee of erasure of HTTP/TLS, OS, clipboard, swap or crash-dump copies. Do not collect/share dumps or logs with secrets. There is no automatic update mechanism. The backend is intended to retain only a short-lived RAM snapshot; its actual deployed behavior must be independently verified.

## Checks and verification

The public CI checks Rust formatting, Clippy, tests, Windows packaging, secret scanning, locked-dependency advisories and a ClamAV scan of the actual packaged EXE. Dependabot proposes dependency updates. The release workflow requires a matching protected version tag, successful CI for the exact main commit, and hosted-runner provenance for the ZIP and standalone EXE. Stable releases additionally require the HTTPS routing/authentication preflight. Release creation is disabled by unconditional source and private-artifact-handoff gates; the release build job has read-only rights. An approved protected publisher and separate review are required. VirusTotal is a mandatory fail-closed gate: no key, missing, stale, malformed or incomplete results, API failure, or any malicious/suspicious result blocks release. Submission requires separate explicit permission; only the exact final EXE may be submitted. The redacted engine-level report, checksums, Cargo SBOM and build evidence are retained even when a scan fails, without binary artifacts. See docs/release-security.md for policies, prerequisites, limitations and signing preparation. Zero detections are not proof of safety. Pre-releases are not proof of production availability or real-game compatibility.

Download from GitHub Releases, verify SHA-256, and verify provenance with gh attestation verify <file> --repo EarlySalty/deadlock-live-match-collector. Preserve third-party notices. Do not disable endpoint protection. Report suspected vulnerabilities privately using GitHub's private vulnerability reporting if enabled; never include actual connection keys, live personal data or memory dumps in public issues.
